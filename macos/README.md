# Индикатор лимитов в менюбаре macOS

Два кольца в статус-баре: слева пятичасовое окно, справа недельное.
Данные и весь расчёт берутся у `cc-limits --indicator`, своей логики лимитов
приложение не имеет.

## Что показывают кольца

| Канал | Что кодирует |
| --- | --- |
| Длина дуги | сколько бюджета выработано |
| Цвет дуги | зона **накопленного темпа** по всему окну |
| Диск в центре | **рывок**: темп последней единицы окна (час из пяти, сутки из семи) |
| Красный ободок | бюджет выбран, дальше идёт резерв (чужая доля) |

Цвет отвечает на вопрос «не слишком ли быстро я ем», а не «сколько осталось».
Кончившиеся лимиты видно и без индикатора - по отказам агентов, красить их
незачем. Шкала одна для обоих каналов:

| Зона | Условие | Смысл |
| --- | --- | --- |
| бирюзовый | pace < 0.5 | к сбросу съешь меньше половины, можно жать сильнее |
| зелёный | 0.5 ≤ pace ≤ 1.0 | приходишь к сбросу примерно на нуле |
| янтарный | 1.0 < pace ≤ 1.33 | сухим просидишь до четверти окна |
| красный | pace > 1.33 | сухим просидишь больше четверти окна |

`pace` - накопленный темп в долях равномерного (`pct / expected`). При таком
темпе 100% наступает на доле окна `1/pace`, то есть без лимитов остаёшься
`1 - 1/pace` окна. Пороги заданы именно через это, поэтому одинаково
осмысленны и для пяти часов, и для недели.

Диаметр диска линеен по темпу рывка: полный диск - вдвое быстрее равномерного.
Кольцо зелёное, а диск красный - по окну идёшь нормально, но прямо сейчас
ешь слишком быстро.

Клик открывает меню с разбором по каждому аккаунту и пунктом «Настройки...».

## Сборка и запуск

```sh
swift build -c release
.build/release/CCLimitsBar &
```

Приложение ставит себе `.accessory`-политику, поэтому иконки в доке нет и
бандл `.app` не нужен. Иконка рисуется вектором через `drawingHandler`, так
что остаётся чёткой на любом Retina и сама перекрашивается под светлую и
тёмную тему менюбара.

Автозапуск включается в настройках: пишется
`~/Library/LaunchAgents/com.cc-limits.bar.plist`, он подхватится при
следующем входе в систему.

## Настройки

Аккаунты, резервы и поведение бара правятся в окне настроек. Для каждого
аккаунта видно отпечаток токена, наличие scope `user:profile` и возраст кэша;
записи с одним и тем же токеном подсвечиваются - иначе одни и те же цифры
показывались бы под двумя именами.

Переключатель «Показывать» скрывает аккаунт, не удаляя его: запись остаётся в
конфиге целиком (`"hidden": true`), но уходит из колец, меню и статуслайна.
Нужно, когда токен держат про запас - например, токен от `claude setup-token`
лимиты не отдаёт, а описание команды его получения терять жалко. По явному
`cc-limits --account ИМЯ` скрытый аккаунт по-прежнему доступен.

Конфиг общий с CLI - `$CLAUDE_CONFIG_DIR/cc-limits.json`. Окно никогда не
пишет его напрямую: кандидат уходит во временный файл, его проверяет
`cc-limits --check-config` тем же кодом, который читает рабочий конфиг, и
только при нулевом коде возврата файл подменяется атомарно. Ключи, которых
окно не знает, переносятся в новый файл нетронутыми.

Настройки самого бара (аккаунт на иконке, интервал опроса) лежат отдельно, в
`$CLAUDE_CONFIG_DIR/cc-limits-bar.json`: CLI про них ничего не знает.
